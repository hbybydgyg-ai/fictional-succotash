صدى العراق — الإصدار الظاهر داخل التطبيق 2.3

خدمات يدوية لا تعتمد على مزود:
- إضافة «خدمات بدون مزود» إلى إدارة الخدمات؛ تستطيع الإدارة إنشاء خدمة باسم ووصف ومنصة وقسم موجود أو جديد.
- تحديد أقل وأعلى كمية وسعر البيع لكل 1000 وحدة بالدولار وحد الطلب لكل حساب خلال 24 ساعة (0 يعني عدم وضع حد).
- تظهر الخدمة في كتالوج الموقع وفي القسم المحدد، لكنها لا تُضاف إلى كتالوج API العام للمزودين ولا تستدعي أي مزود عند الطلب.
- إنشاء سجل طلب حقيقي داخل صدى العراق برقم طلب عام، مع خصم السعر من رصيد المستخدم إذا كان كافياً، وحالة «بانتظار التواصل مع الدعم» ورسالة منسقة قابلة للنسخ من نافذة النجاح وصفحة الطلبات.
- منع الطلبات المكررة، التحقق من الرابط والكمية والسعر وحالة الخدمة، واستخدام معاملة Firebase ذرّية للرصيد وحد الطلب لكل خدمة وحساب.
- حفظ الخدمات اليدوية ضمن ملف بيانات الاستضافة وإدراج الملف في النسخ الاحتياطية الإدارية؛ أظهر الخادم تحذيراً عند عدم اكتشاف تخزين دائم.

الحفاظ على الميزات السابقة:
- إعادة اختبار الخدمات المجانية الممولة من حساب الإدارة، بما فيها إرسال الطلب الحقيقي إلى مزود الاختبار بسعر صفر للمستخدم وحد مستقل لكل خدمة، وعدم تغيير الخدمات المدفوعة العادية.
- إصلاح ترتيب سكربت الخدمة اليدوية حتى يأتي بعد سكربتات الطلبات القديمة، وإعادة استخدام قائمة الأقسام لتجنب تكرار عناصر DOM عند فتح نافذة الإدارة.
- تحديث الإصدار الظاهر في الشريط الجانبي فقط إلى 2.3. تبقى علامات البناء التقنية 1.6.41 كما هي للمحافظة على فحص التوافق الحالي للخادم والواجهة.

الاختبارات:
- npm test: الفحوص الثابتة، واختبارات API بخادم وFirebase ومزود محليين وهميين، واختبارات آسياسيل الوهمية.
- فحص نحوي لجميع 75 سكربتاً مضمناً في index.html.
- لا تمثل هذه الاختبارات نشراً على Railway أو اتصالاً بقاعدة الإنتاج أو مزود حي، ولم تُجر عمليات مالية حقيقية.

تنظيف الكود:
- حذف المساعدين غير المستخدمين المضافين حديثاً، وإزالة إنشاء عناصر قائمة الأقسام المكررة.
- لم تُحذف سكربتات الواجهة القديمة أو الملفات الموجودة مسبقاً بشكل جماعي؛ المشروع يعتمد على مجموعة معالجات متتابعة لبعض وظائف الواجهة، وحذفها دون تحليل واعٍ قد يكسر الطلبات أو تسجيل الدخول أو آسياسيل.
